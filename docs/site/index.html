Principles

What a console actually is

A session outlives the browser — it runs independent of any client connection, so closing the tab doesn't stop it.

Reattaching replays what you missed — output is buffered from the moment a session starts, whether or not anyone is watching.

Live output streams over WebSocket — a connected browser gets new output pushed in real time, not polled.

A session's identity is its own, separate from whichever worktree or checkout it happens to run in — more than one session can point at the same directory.

The launch command is the agent — a plain shell, or a CLI such as claude or codex, chosen per console.

How it works

One console, start to reattach

Each of an issue's consoles is one persistent terminal in its own git worktree; this is what opening one actually does.

  1. 1sidenav

    Pick a project

    The sidenav renders a project's issues as a filterable tree of initiatives and tasks — text, ship-status, and tag filters, pinning, and a live indicator when a node has an open console.

    ProducesTree
  2. 2flow steps

    Open an issue

    An issue's detail carries its flow steps, branch, PR, and checks summary, plus any past Claude/Codex conversation captured in one of its consoles, ready to reopen.

    ProducesFlow steps
  3. 3worktree

    Launch a console

    A console starts a long-lived PTY process in a fresh git worktree or the main checkout. It keeps running on the server independent of any single browser connection.

    ProducesPTY session
  4. 4claude · codex · shell

    Choose an agent

    Each console launches with whatever command it's given — a plain shell, or an agent CLI such as claude or codex — with several staying open in tabs at once.

    ProducesLive terminal
  5. 5any browser

    Reattach from anywhere

    A background thread keeps draining the session's output into a buffer the whole time, so reconnecting from a new browser replays everything missed instead of losing it.

    ProducesResumed

A session is not a job. It's a live process someone watches and types into, closer to a terminal you can walk away from than a task you submit and poll for a result. The working directory is incidental — a session's identity is separate from whichever worktree or checkout it runs in, so more than one session can point at the same directory.

Multiple browsers, one session. Attaching to a session that's already running joins the existing process rather than starting a new one — its buffered output brings a fresh browser fully caught up. Real time, over WebSocket. A connected browser gets new output pushed live, not polled.

Features

What's in the client

One card per component; the components themselves (client/src/app/components/) are the source — this only names the shape.

app-sidenavNavigation

Filterable tree of a project's initiatives and tasks — text, ship-status, and tag filters, pinning, and a live attention indicator when a console needs you.

app-console-tabsTerminal

Multiple consoles stay open in tabs per issue or project, each backed by its own persistent PTY and its own agent choice.

app-agent-pickerTerminal

The claude/codex/shell chooser, shared between an issue's console and a project-level one.

app-session-listSessions

Past Claude/Codex conversations captured in an issue's consoles, listed on its Overview tab and reopenable to resume exactly where they left off.

app-overviewLanding

The workspace landing page: per-project issue totals — open, closed, initiatives, tasks — composed client-side from the same tree the sidenav uses.

app-usage-widgetUsage

Tracks remaining LLM usage against the engine's own cache, shifting color as a window runs low.

Reference

Engine and client, package by package

What each part of the source actually does.

Engine

Spring Boot, packaged under dev.locklane.engine: github syncs issues and PRs, pty runs the terminal processes (PtySession, SessionRegistry, OutputBuffer), ws streams terminal I/O and events to the browser over WebSocket, persistence holds SQLite and its migrations, security gates access, usage tracks LLM quota.

Client

An Angular PWA (client/) of standalone components backed by services — ProjectsService, IssuesService, ConsolesService, AgentStore — rather than a single central store.

Sessions

SessionRegistry tracks which sessions are open across engine restarts. Attaching to a session id that already has a running process joins it instead of starting a new one — a session's identity is independent of the worktree or checkout it runs in, so more than one session can point at the same directory.

Terminal environment

A session launched from a context with no real terminal attached — an IDE run configuration, systemd — gets a default TERM/COLORTERM so CLI output still gets color; an environment that already sets its own is left alone.

Storage

SQLite, configured in application.yml, with its own migration set under persistence/migration.
