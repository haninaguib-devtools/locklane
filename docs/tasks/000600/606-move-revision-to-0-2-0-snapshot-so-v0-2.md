# 606 — Move revision to 0.2.0-SNAPSHOT so v0.2.0 can be cut
Issue: #606

## Asked
Move `pom.xml`'s `<revision>` from `0.1.14-SNAPSHOT` to `0.2.0-SNAPSHOT`, so that what
is currently on `main` can be cut as release v0.2.0. The release gate
(`scripts/release.sh gate <version>`) refuses to cut a version unless `<revision>` reads
`<version>-SNAPSHOT`, and `main` was building toward 0.1.14; the next release is to be a
minor one, 0.2.0, rather than 0.1.14.

## Done when
- `pom.xml`'s `<revision>` reads `0.2.0-SNAPSHOT`:
  `grep -q '<revision>0.2.0-SNAPSHOT</revision>' pom.xml`
- `scripts/release.sh gate 0.2.0` exits 0 once this PR is merged to `main`.

## Explicitly not
- Does not cut, tag, or dispatch anything — release v0.2.0 is cut afterwards by
  `/l-release 0.2.0`, which lands the `CHANGELOG.md` section and the follow-on bump to
  `0.2.1-SNAPSHOT` in its own task.
- Does not touch `CHANGELOG.md`; the v0.2.0 notes are generated by that release task.

## Decisions made along the way
- The next release is 0.2.0, skipping 0.1.14 entirely (the human, 2026-09-02, when
  `/l-release`'s gate refused 0.2.0 against a `0.1.14-SNAPSHOT` revision).
