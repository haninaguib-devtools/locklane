Install

Run LockLane locally

curl
$ curl -fsSL https://raw.githubusercontent.com/haninaguib-devtools/locklane/main/install.sh | bash

Requires Java 21+ and the authenticated GitHub CLI while the repository is private. The installer places the jar, updater, uninstaller, and local configuration in ~/.locklane, alongside three small control scripts — status.sh, stop.sh, and start.sh — that already know how the server was installed, so checking on it or restarting it (stop.sh then start.sh) never depends on which service manager your machine uses.

There is no second step: the installer starts the server for you and registers it to keep running — as a per-user background service, a systemd user service on Linux or a launchd agent on macOS, so it comes back after a reboot and restarts itself if it crashes. On a host with neither, it starts the server detached instead; that copy runs until the machine restarts, and you start it again yourself afterwards.

To remove LockLane, run ~/.locklane/uninstall.sh. It stops the server and de-registers the service, then asks separately whether to delete ~/.locklane along with the accounts, projects, and database inside it — keeping your data unless you say otherwise.

What is LockLane?

Agent work that stays visible.

Coding agents are easy to start and difficult to keep oriented. LockLane gives each piece of work a durable place: the issue that describes it, the worktree that isolates it, and the live terminal where the agent is running.

It is not a job queue and it does not replace git, GitHub, or your agent. It is the workspace connecting them.

[*]

Issue-aware

Projects, initiatives, tasks, pull requests, and dependencies remain attached to the workspace doing the work.

[*]

Persistent sessions

Terminal processes keep running when the tab closes. Reattach later from another browser and continue where you left off.

[*]

Isolated by git

Issue consoles run in separate git worktrees, so multiple agents can work in parallel without sharing a checkout.

[*]

Human-controlled

Agents can plan, implement, and review. Moving work into main still waits for an explicit human confirmation.

The working model

One visible path from issue to merge.

  1. 01

    Import a repository

    LockLane checks out the project and reads its GitHub issue structure.

    repository → project
  2. 02

    Open a console

    Start a plain shell or a coding agent in a worktree created for that task.

    issue → worktree → PTY
  3. 03

    Stay through delivery

    Follow the session, checks, review, and pull request without losing the task context.

    work → review → human gate

Under the hood

Built from ordinary tools.

A Spring Boot engine serves an Angular PWA, keeps non-binding state in SQLite, manages normal git worktrees, and exposes live terminal processes through the browser.
